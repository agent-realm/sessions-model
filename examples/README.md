# Examples

sessions-model records, from the smallest valid session to a full one. Each directory
holds ordered JSONL, one record per line, and a README that says what to look at.

| Example | What it shows |
|---|---|
| [01-one-message](01-one-message/) | One session, one message |
| [02-parts-and-tools](02-parts-and-tools/) | Parts and a tool call |
| [03-usage](03-usage/) | Usage, and the two flags |
| [04-links](04-links/) | Links: a fork and a sub-agent |
| [05-lifecycle](05-lifecycle/) | Lifecycle: retraction and destruction |
| [06-full-session](06-full-session/) | A full session |

**Validated.** Every file was generated by [`generate.mjs`](generate.mjs), sealed and checked with
`seal()` and `validateSession()` from the reference provider (`packages/session-adapters` in [harness-skeleton](https://github.com/agent-realm/harness-skeleton)):
0 findings. To re-check:

```sh
node generate.mjs <path to packages/session-adapters> .
```

All values are synthetic. The `host` is the contract's own known-answer value for a synthetic machine id.

Which harness: 01 to 03 and the retraction in 05 use Claude Code and Gemini CLI, which record those
things. The links in 04, the destructive rewind in 05 and the compaction in 06 use the harness id
`reference-harness`, the reference harness harness-skeleton plans, whose own store records each of
them explicitly; the [annex](../contracts/sessions-model-annex.md) does not record them for Claude
Code.
